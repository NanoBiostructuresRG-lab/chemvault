# CHEMVAULT

**A traceable molecular dataset management and curation application**

[![License: LGPL v3](https://img.shields.io/badge/License-LGPL_v3-blue.svg)](LICENSE)

---

## What is CHEMVAULT?

**CHEMVAULT** is a visual, no-code molecular dataset management and curation
application for creating, organizing, tracing, and exporting molecular and
structured activity datasets from PubChem or CSV sources.

It provides traceable workflows for target-based dataset construction, SMILES
harmonization, structured activity filtering, preservation of PubChem activity
labels, structure consolidation, and dataset modelability assessment.

CHEMVAULT can:

- build SQLite databases from one PubChem protein target, resolved from a gene
  symbol and organism or supplied directly as a UniProt accession, or from CSV
  files;
- inspect, filter, and export molecular and structured activity data;
- harmonize PubChem-derived molecular structures through HARMONSMILE;
- preserve PubChem `Active` and `Inactive` activity labels;
- consolidate repeated observations by harmonized molecular structure;
- evaluate structure-label neighborhood consistency with the
  **MODELABILITY INDEX**;
- preserve target identity, provenance, persisted job state, reusable
  fingerprint artifacts, and downloadable analysis outputs.

CHEMVAULT is **not** a machine-learning training application. It does not fit
predictive models, define activity thresholds, or implement molecular
fingerprint algorithms. The MODELABILITY INDEX workflow consumes fingerprints
generated by [MOLRAPTOR](https://pypi.org/project/molraptor/) and evaluates the
organization of the labeled dataset.

CHEMVAULT is developed and maintained by the
[NanoBiostructures Research Group](https://github.com/NanoBiostructuresRG-lab).

## Core workflow

```text
CSV input
    |
    v
SQLite table
    |
    v
Explore, refine, derive tables, and export CSV


Gene symbol + organism -> reviewed UniProt accession
                                      |
Direct UniProt accession -------------+
                                      |
                                      v
                            PubChem protein search
                                      |
                                      v
                  Molecular, assay, and structured activity tables
                                      |
                                      v
                     SMILES HARMONIZED (HARMONSMILE)
                                      |
                                      v
                       Structured activity filtering
                                      |
                                      v
                 ACTIVITY LABELS and structure consolidation
                                      |
                                      v
                 MODELABILITY INDEX (MOLRAPTOR fingerprints)
                                      |
                                      v
             Nearest-neighbor report and fingerprint .npz export
```

CHEMVAULT keeps source tables available and records derived-table provenance so
that curated and analytical outputs remain traceable to their inputs.

## Who is it for?

CHEMVAULT is intended for researchers in chemistry, biochemistry,
cheminformatics, chemical biology, and related fields who need a reproducible
visual workflow for preparing molecular datasets without writing application
code.

## Installation

> **Windows:** Anaconda Prompt, PowerShell, or the VS Code integrated terminal
> can be used when Conda is configured.
>
> **macOS / Linux:** use the system terminal.

CHEMVAULT is distributed from GitHub release tags. It is not installed from
PyPI. Compatible versions of HARMONSMILE, CHAMANP, MOLRAPTOR, and the remaining
runtime dependencies are installed from `requirements.txt`.

1. Clone the repository and select the release tag:

```bash
git clone https://github.com/NanoBiostructuresRG-lab/chemvault.git
cd chemvault
git fetch --tags
git checkout v0.13.0
```

2. Create and activate the environment:

```bash
conda create -n chemvault_env python=3.12
conda activate chemvault_env
```

3. Install the pinned dependencies:

```bash
python -m pip install -r requirements.txt
```

4. Run CHEMVAULT:

```bash
streamlit run app.py
```

Open `http://localhost:8501` in your browser.

> Do not install HARMONSMILE, CHAMANP, or MOLRAPTOR separately for normal
> CHEMVAULT use. The compatible versions are defined in `requirements.txt`.

### Updating an existing clone

```bash
cd path/to/chemvault
git fetch --tags origin
git checkout v0.13.0
conda activate chemvault_env
python -m pip install -r requirements.txt
```

A release checkout is normally in a detached `HEAD` state. That is expected
when running a tagged version.

## Execution modes

CHEMVAULT supports two execution modes.

### Local mode

Local mode is the default and recommended mode for normal use:

```bash
streamlit run app.py
```

```text
Streamlit UI -> application/services -> SQLite
```

FastAPI is not required. Local mode is selected whenever
`CHEMVAULT_API_URL` is not configured.

### API-client mode

API-client mode is intended for development and validation of the supported
Streamlit-to-FastAPI path.

Start FastAPI in one terminal:

```bash
python -m uvicorn api.main:app --reload
```

Start Streamlit in a second terminal.

Windows PowerShell:

```powershell
$env:CHEMVAULT_API_URL = "http://127.0.0.1:8000"
streamlit run app.py
```

macOS / Linux:

```bash
export CHEMVAULT_API_URL="http://127.0.0.1:8000"
streamlit run app.py
```

```text
Streamlit UI -> HTTP client -> FastAPI -> application/services -> SQLite
```

Interactive API documentation is available at
`http://127.0.0.1:8000/docs`. See [docs/api.md](docs/api.md) for the endpoint
contract and current limitations.

CHEMVAULT does not silently fall back to local execution when
`CHEMVAULT_API_URL` is configured and the backend is unavailable.

To return to local mode:

Windows PowerShell:

```powershell
Remove-Item Env:CHEMVAULT_API_URL -ErrorAction SilentlyContinue
streamlit run app.py
```

macOS / Linux:

```bash
unset CHEMVAULT_API_URL
streamlit run app.py
```

### Current API-client coverage

The HTTP path supports selected database inspection and export operations,
strict UniProt gene-target resolution, PubChem protein-search jobs, structure
consolidation, HARMONSMILE jobs, MODELABILITY INDEX jobs, and fingerprint
`.npz` export through the backend gateway.

CHAMANP execution and unsupported table mutations remain local workflows. The
current backend runtime is process-local and is not a distributed worker
platform.

## Quick start

### From a CSV file

1. Start CHEMVAULT and open `http://localhost:8501`.
2. Enter a name in **SQL Database name**.
3. Upload `examples/example_chamanp.csv` from the sidebar.
4. Inspect the table using the **Columns** controls.
5. Use **Refine** to filter rows or columns.
6. Create a derived table when the selection should be preserved.
7. Use **Download CSV** to export the active selection.

### From PubChem to MODELABILITY INDEX

1. Start CHEMVAULT and enter a database name.
2. Select **Select Target**.
3. Choose one target-input mode:
   - enter a gene symbol and organism, then resolve it to one reviewed UniProt
     accession; `LEPR` with Homo sapiens taxonomy identifier `9606` resolves to
     `P48357`;
   - enter one UniProt accession directly; `P34971` is a practical smoke-test
     target.
4. Confirm the target and launch the PubChem search.
5. Follow the persisted PubChem job in the progress dialog. Completed searches
   populate `main`, `compound_assays`, and `compound_activities`.
6. Create or select a Structured activity subset for the activity type and
   population of interest.
7. Run **SMILES HARMONIZED** on its CID column.
8. Run **ACTIVITY LABELS** to preserve binary PubChem outcomes and consolidate
   repeated observations by `SMILES_Harmonized`.
9. Select the resulting consolidated table.
10. Choose a fingerprint in **MODELABILITY INDEX** and run the analysis.
11. Inspect the score, class concordance, provenance, and nearest-neighbor
    report.
12. Download the nearest-neighbor report or the fingerprint `.npz` export.

> Databases are stored in `SQL/` and can be reopened in later sessions. Use a
> different database name when a completely fresh run is required.

## PubChem jobs and database persistence

PubChem protein searches are stored as persisted jobs in the selected SQLite
database. Long searches continue through the selected backend runtime while it
remains active, and the interface shows status, stage, progress, and messages.
Searches can be cancelled safely with **Cancel search**.

CHEMVAULT creates and maintains separate tables for molecular records, assay
metadata, and structured activity observations. Derived tables remain inside
the same database with provenance and operation history.

For newly completed target-based builds, CHEMVAULT persists the input mode and
canonical UniProt accession together with resolved gene, organism, protein,
and review-status metadata when available. The Database summary displays this
`Target identity` provenance. Legacy databases remain readable without
inferred or silently backfilled target metadata.

## Structured activity

Structured PubChem activity is stored in `compound_activities`, separately from
the main molecular table.

The interface supports filtering by fields such as:

- activity type;
- unit;
- PubChem outcome;
- AID;
- numeric activity range when a compatible activity type and unit are
  selected.

The on-screen preview may be bounded for responsiveness, while **Download CSV**
exports the complete filtered result.

Structured activity subsets provide the traceable inputs for the
**ACTIVITY LABELS** workflow.

## SMILES HARMONIZED

The **SMILES HARMONIZED** workflow is powered by
[HARMONSMILE](https://pypi.org/project/harmonsmile/). It accepts a valid PubChem
CID column and merges normalized molecular output back into the selected
table.

Important output fields include:

- `PubChem_CID` - canonical PubChem identifier;
- `SMILES_RDKit` - the RDKit-derived representation used during processing;
- `SMILES_Harmonized` - the final harmonized representation used by
  CHEMVAULT downstream workflows;
- `SMILES_Harmonization_Status` - `ok`, `ok_with_warnings`, `unsupported`, or
  `failed`;
- `SMILES_Harmonization_Message` - record-level diagnostic information;
- `InChI` and `InChIKey` when provided by the PubChem workflow.

`SMILES_Harmonized`, not `SMILES_RDKit`, is the structural key used by
ACTIVITY LABELS, structure consolidation, and MODELABILITY INDEX.

## ACTIVITY LABELS and structure consolidation

The **ACTIVITY LABELS** workflow operates on eligible Structured activity
tables after SMILES harmonization.

It:

- preserves PubChem `Active` and `Inactive` outcomes;
- does not introduce pEC50, pKi, or other threshold-based labels;
- groups observations by `SMILES_Harmonized`;
- retains one structure-level record when the available observations agree;
- excludes conflicting structure-level outcomes traceably;
- preserves reference identifiers and contributing AIDs;
- leaves the source HARMONSMILE-enriched table unchanged.

The resulting table follows the
`activity_subset_<activity>_structure_consolidated` naming contract, with
numbered suffixes when necessary.

## MODELABILITY INDEX

The **MODELABILITY INDEX** evaluates whether binary activity labels are locally
consistent in molecular fingerprint space. For each eligible structure,
CHEMVAULT identifies its nearest neighbor by Tanimoto similarity and measures
same-class concordance for `Active` and `Inactive` structures. The final score
is the macro average of the two class concordances.

A value closer to 1 indicates stronger local agreement between molecular
similarity and the preserved binary labels. It is a dataset diagnostic, not a
guarantee of predictive performance.

### Fingerprint representations

CHEMVAULT v0.13.0 supports the following MOLRAPTOR fingerprints:

- Morgan - default;
- Feature Morgan;
- Atom Pair;
- RDKit Topological;
- Topological Torsion;
- Layered;
- MACCS.

Analyses are scoped by database, source table, and fingerprint type. Compatible
completed results and persisted fingerprint artifacts can be restored and
reused without confusing different molecular representations.

CHEMVAULT records the resolved fingerprint profile, vector size, dependency
versions, analysis identity, and related provenance. It does not implement the
fingerprint algorithms; encoding is provided by MOLRAPTOR.

### Downloads

The result card provides:

- a complete nearest-neighbor report;
- a self-contained fingerprint `.npz` export containing the fingerprint
  matrix, ordered harmonized SMILES, binary outcomes and labels, stable
  structure identifiers, and canonical provenance metadata.

The `.npz` filename contract is:

```text
<database_id>_<activity_type>_fingerprints_<analysis8>.npz
```

## Table Manager and operation history

The **Table Manager** supports inspection of database tables, schema,
provenance, and operation history. Derived tables can be removed when they are
no longer needed. Database-maintenance controls are grouped separately from
normal curation and analysis actions.
